# Crimson Desert Telemetry 2.2.0

Two new things: telemetry now sees lights all around you, and it can tell which of them actually reach you.

- **Lights all around you.** Telemetry now reads the game's light list *before* the renderer drops what the current view cannot see. Lights behind the camera and out of view stay in the API, the radar and the fullscreen markers. A fire bowl arrives as one light instead of dozens of flickering particles.
- **Which lights reach you.** The game's own physics casts nine rays from the camera to every light within `[LightOverlay] Radius` (100 game units around the player in the supplied INI). A wall blocks all nine; a lantern cage blocks only some rays, so the lantern stays visible. The HUD dims blocked lights, F11 hides them, and the API reports `clear` / `blocked` / `unknown` per light. **On by default**; `[SourceVisibility] Enabled=0` switches it off.
- Radar and markers: filled dots are lights the renderer uses in this view; hollow rings are current lights it does not use here (not OFF). Detail cards show fire groups (`GROUP of N`) and renderer selection.
- API: snapshot schema **1.6** adds `lights.upstream` (all current engine lights of a capture, with `rendererSelected`) and physics `sourceVisibility` (method `physics-ray-fan`, ray counts, measurement age) on upstream and rendered lights. A rendered contribution reports the result of its upstream light. Routes stay HTTP API v1; existing records and RGB values are unchanged.
- The HUD uses the all-around list when available and falls back to renderer output, labelled `RENDERED ONLY`, when it is not. With upstream capture enabled, the smoothed feed stays on that source and reports `unavailable` if it is missing; it does not silently switch to the view-filtered list. With upstream capture disabled, smoothing uses renderer output.
- Same target as 2.1.14: **Crimson Desert patch 2.03.02** on Steam for Windows (EXE `1.0.0.2976`, Steam build `25477059`). Unknown executables still fail closed.

Upgrading: close the game, merge your preferences into the new INI (new keys `[Lights] Upstream=1`, `[SourceVisibility] Enabled=1`, `[LightOverlay] Radius=100`) and deploy the complete ZIP.

Known limitations:

- Visibility is a sampled collision estimate, not how much light gets through. Thin gaps can make a light behind a fence or cage `clear`, and geometry without collision (foliage, some decorations) does not block. Results expire after 500 ms and are never used to remove API records.
- Up to 256 lights share a budget of 20 physics batches per second; with many lights in the radius each light refreshes less often, and stale results show as `unknown`.
- The all-around list covers the lights the game currently hands to the renderer. It is not a persistent world registry; a missing light does not prove it is OFF.
- Each light sample now copies a second 1.5 MB buffer on the GPU. Its cost was not measured separately.
- Camera-local sky visibility and derived local ambient RGB can still be unavailable on patch 2.03.02, as in 2.1.14.
- One private physics test session hung while loading. The owner attributed it to a wrong file; the cause was not established.
