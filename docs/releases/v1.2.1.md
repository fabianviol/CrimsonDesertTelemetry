# Crimson Desert Telemetry v1.2.1

This release repairs player telemetry for Steam build `25116796`. In v1.2.0 the
player position was actually the renderer camera, and the player orientation was
never published at all. Both are fixed and verified against the running game.

## What was wrong

- `player.position` reported the renderer camera. The two values were
  bit-identical, roughly 6.5 units apart from the player. The pattern that had
  located the player global before the update no longer matched, and its
  replacement resolved to a camera global instead.
- Player orientation was silently absent. The v1.2.0 release notes described an
  SQT player transform; that object exists but holds neither a position nor a
  rotation, so every sample was rejected and nothing was published. That claim is
  withdrawn.

## What changed

- The genuine player-position global is located by the shape of its writing code
  rather than by exact bytes, which the compiler had changed. Of 4816 candidate
  globals exactly one is chunk-aligned to the physics root; it was validated live
  over 27 units of player movement.
- Player orientation is published again. The transform is the unchanged
  `basis-v1` physics layout; only the physics link had moved. Verified live: over
  22 samples the player heading swept 355 degrees while the camera held still for
  seven of them, so the two are independent sources, and the root basis stayed
  upright throughout.
- Orientation no longer flickers out during fast movement. The position agreement
  check is an identity check, not a freshness check, and its tolerance now says
  so. The previous 0.15-unit limit also demanded that both values come from the
  same frame, which rejected 3.6% of samples while riding.
- A missing orientation now reports why, naming the failing step of the pointer
  chain and the values that failed validation, instead of returning a silent
  null.

## Compatibility

Schema and endpoints are unchanged. `player.position` now moves by about 6.5
units relative to v1.2.0 on build `25116796`, because it reports the player
rather than the camera. Consumers that treated it as an eye position should use
`camera.position` instead.

The package requires an x64 ASI loader and the Microsoft .NET 8 ASP.NET Core
Runtime (x64). The in-game HUD and light module both remain disabled by default.
