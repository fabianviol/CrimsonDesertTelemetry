# Crimson Desert Telemetry 2.0.0

Live lighting telemetry for Crimson Desert: inspect current rendered light
contributions in an in-game 3D radar and fullscreen overlay, or consume their
positions, HDR RGB and spotlight geometry through a local HTTP/WebSocket API.
Independent player and camera telemetry share the same single-ASI package.

[Watch the in-game demonstration](https://youtu.be/eyRkkTXAU64).

![Crimson Desert Telemetry lighting radar and fullscreen light overlay](https://raw.githubusercontent.com/fabianviol/CrimsonDesertTelemetry/v2.0.0/media/screenshot1.jpg)

## New in 2.0

- Current rendered light contributions through the local HTTP/WebSocket API:
  world position, linear HDR RGB, derived luminance and recognized spot direction
  and cone angle. Authored light records remain separately available.
- Paired GPU valid-prefix counter and camera data exclude stale buffer-tail
  "ghost lights" and reconstruct world positions from the captured frame.
- Fullscreen light markers and an enlarged 3D light radar with a pitch/roll-aware
  camera frustum. Nearby contributions share a detail panel without combining or
  smoothing the original measurements. F8 toggles the corner HUD, F9 diagnostics,
  F10 the fullscreen light overlay.
- Lights, both HUD views and notifications are enabled in the included INI.
- Unified ASI: the telemetry bootstrap, native light capture and optional research
  console no longer require two plugins. The console is disabled by default.
- Silent normal startup/loading. Success is triggered once the API reports playing
  and the requested data is fresh, which can occur during visible loading. Its
  configured duration is six seconds. Actionable errors may appear immediately,
  including unknown EXEs and missing host/runtime files, independently of game hooks.
- Shared managed/native build contract, stricter profile validation and native
  hook/caller-context checks. `check-update <exe>` gives an offline recovery report;
  it never enables an unverified build. Native regression tests now run in PR CI.

## Install / upgrade

Close Crimson Desert before replacing the package. In DMM or JSON Mod Manager,
disable the previous telemetry and CrimsonHueConsole packages, then enable the
single 2.0.0 ZIP. Do not leave the old console ASI in a loader search path.
The package requires an x64 ASI loader and the .NET 8 ASP.NET Core Runtime (x64).
Restart after INI changes; hot-unload is unsupported. Disabling the corner HUD
alone does not disable fullscreen markers, notifications or native light capture.

HTTP routes remain `/v1/*`. Enabling lights uses additive JSON schema 1.4; disabling
`[Lights] Enabled` retains schema 1.1. The default endpoint is
`http://127.0.0.1:27311`. Package version 2.0 does not rename the API routes or
introduce a schema 2.0 contract. CrimsonHue remains a separate future consumer;
this release exposes telemetry and does not control Philips Hue lamps.

The installed 2.0.0 package passed a fresh game start and a progressing API check
on the supported build: independent player/camera poses, available authored and
rendered lights, advancing capture/frame counters, zero malformed light records
and no health error. The user confirmed the in-game result and accepted the
success notice appearing as data arrives during loading.

Release verification passed 56 managed tests, the HTTP/WebSocket smoke test,

visualization and notification checks. See

## Compatibility and limits

Native lighting targets the validated Steam build 25116796 / EXE 1.0.0.2760 and
requires its exact SHA-256 and guarded instructions. Unknown builds fail closed
for native instrumentation; offline candidates are not automatic compatibility.
Future shader-only asset changes are not completely detected by an EXE hash.

The current feed is filtered renderer data, not a complete registry of every light.
A missing contribution is not a permanent OFF state; stable physical-object IDs,
physical lumens and complete sun/sky/emissive coverage are not claimed. Linear HDR
values can vary with effects and exposure. Authored and rendered arrays overlap
and must not be summed. Marker colors are SDR visualizations, not final pixel colors.

The camera and light paths have no DLSS, Streamline or NVIDIA runtime dependency.
In-game validation used NVIDIA hardware; AMD and Intel game setups remain untested.
The overlay supports D3D12 with an 8-bit SDR swapchain. HDR is unsupported;
frame generation and other graphics combinations remain unvalidated. Graphics-hook
failures can prevent on-screen notices, so bootstrap/native/overlay logs remain
available. Markers have no scene depth test and may be drawn through walls.

The external host reads game memory, while native light capture instruments the
renderer with guarded hooks and GPU readback. This is not an untouched game run.
Returning to the title screen can leave HUD/data visible for several seconds
until it becomes stale or another load occurs. This accepted behavior remains;
F8 and F10 can hide the views. Precise motion alignment/latency and normalized
exposure are not established by the local checks.
